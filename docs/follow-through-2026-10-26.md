## Provider and CSP decisions

Retain public OSM for current local/low-volume use, with visible attribution and ordinary browser caching. Its [tile policy](https://operations.osmfoundation.org/policies/tiles/) provides no SLA and prohibits bulk prefetch. A paid raster provider can use the existing three environment settings without replacing the map UI. For vector labels/native night styling, evaluate a licensed vector integration on a separate branch; [Mapbox’s language example](https://docs.mapbox.com/mapbox-gl-js/example/language-switch/) demonstrates this capability and requires a token. Compare Thai/Japanese coverage, attribution, allowed caching, public-token restrictions, quota alerts, actual monthly usage and mobile payload before choosing. No pricing promise or unconfigured provider is shipped.

The installed Next 16 CSP guide documents that nonce-based CSP requires dynamic rendering. Applying a nonce header to this static build would break hydration/scripts or caching assumptions. Preserve the current production policy for this release, with React escaping, bounded imports, no inline event handlers, no eval and no remote frames. A stricter nonce change needs a separate measured rollout; static SRI is experimental and is not a substitute for authorizing every inline script. This is a security review and regression check, not a penetration test.

## Release and external acceptance

Run `node scripts/check-deployment.mjs --self-test` locally. After deployment, run `node scripts/check-deployment.mjs https://YOUR-REAL-ORIGIN`; failures return a nonzero exit code and `test-results/deployment-check.json`. It reads pages only and sends no trip data. For an uptime job, run at a modest interval, alert after two consecutive failures, and retain only status/path/timing evidence. A script in the repository does not imply a live monitor exists.

For calendar acceptance, import a disposable export in Apple Calendar, Google Calendar and Outlook with a non-Japan display timezone: one timed event, one all-day event, multiline Thai/Japanese notes and a midnight boundary. Verify start/end dates, no unintended private notes, and duplicate behavior before sharing real data. No external calendar account is mutated by this release.

Physical-device, native-language, novice-session and field-performance acceptance follow [release operations](release-operations.md). Required owner inputs: deployed origin, monitoring/alert destination, production map account if desired, and reviewers/devices. No fabricated verification is used to fill missing venue fields.

## Verification evidence

Content coverage after this release: 104 last-mile access notes, 20 hours records, 16 admission records, 11 accessibility notes, 5 entrance descriptions and 5 booking notes. Gion additionally has three explicitly inapplicable district-wide fields. Missing fields remain visible in the generated review queue.

The source reachability sweep checked 126 URLs. Nine need manual review because of HTTP 403/500/503 or timeouts; these include retrieved primary-source pages and previously flagged sites. A crawler failure is not evidence of a permanent closure or a stale fact. No review date was advanced solely because a URL responded.

Local verification: lint, typecheck and the 182-route production build passed. The complete Chromium desktop/WebKit mobile suite passed **145 checks with 1 intentional WebKit LCP-observer skip**. Sixteen axe scans across four page/task states, two themes and both browser projects reported zero WCAG A/AA violations after fixing the saved-place contrast defect. Dependency audit reported zero vulnerabilities. Credential guard, deployment-checker self-test and whitespace checks passed. Seven changed Darwin visual references were reviewed, including Thai hero typography, mobile search and budget states. Linux references are verified separately in GitHub Actions.

The first Linux CI run exposed native WebKit button colors with insufficient night-mode contrast in the new trip library and daily overview. These controls now use the existing theme colors and touch-target sizing; the travel-day ordered list also no longer repeats its item numbers. The 30 affected local accessibility, planning and visual checks passed after these refinements. Eight Linux visual references from that run were inspected individually and updated for the intended Thai typography, Japanese search layout and explicit missing-budget states. The final CI run must pass against these reviewed references.

Subsequent Linux testing accepted all visual references and exposed the same native-color issue on place-search buttons. The shared button defaults now use the existing theme palette, with component-specific styling preserved. Accessibility assertions continue through every page so one defect cannot hide later results. Back-to-top links use the browser's [empty-fragment document-top behavior](https://html.spec.whatwg.org/dev/browsing-the-web.html#scroll-to-fragid), avoiding the body element as a scroll target; navigation checks cover this with and without JavaScript. One CI attempt timed out downloading Ubuntu packages; retrying on a fresh runner completed that installation without a code change.

After these changes, all 40 affected local accessibility, navigation, hydration, no-JavaScript and visual checks passed, together with lint, the production build and typecheck.
