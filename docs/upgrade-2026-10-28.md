# 2026-10-28 usability and content refinement

The main change makes finding and using a trip quicker: compact appearance/search controls, an itinerary before management tools, editable personal places, and accommodation addresses usable as route origins. Existing version-1 backups remain valid. No dependency, account, paid service or database was added.

This ledger covers the 44 recommendations in the follow-up audit. “External” means acceptance requires a real deployment, provider account, physical device or human participant; it is not a completed test. Content publication is incremental: an unknown field is still shown as unverified, never filled with a guessed value.

## Verification

Local release checks passed on macOS: lint, TypeScript, production build (182 routes), credential-pattern scan, deployment-checker self-test and dependency audit (zero reported vulnerabilities). After the map lifecycle fix, the full browser suite passed 191 tests with two deliberate skips: WebKit's unsupported LCP observation and its duplicate cross-engine portability run. The six changed macOS visual baselines were inspected; the desktop panel capture uses a taller viewport to include its export controls. Linux baselines and the final workflow outcome are tracked by this release's CI runs.

Automated coverage is not evidence of completed external acceptance above. The new seven-case refinement suite covers parser/privacy boundaries, failed writes and stale drafts, linked-stay lifecycle, repeat-place edits, compact controls, homepage hash navigation and map navigation/reconnection in Chromium, WebKit and Firefox. An independent read-only review identified the older-backup/repeat-visit merge conflict; the shared merge helper now preserves current place metadata, with a regression assertion.

The first [Linux run](https://github.com/araxis07/Website-Japan/actions/runs/40602931720) passed 182 tests, skipped the same two and differed only on the six changed visual references. All six actual images were inspected from its `quality-evidence` artifact before updating the Linux baselines; export controls, search text and both themes remain readable without clipping.

The next [Linux run](https://github.com/araxis07/Website-Japan/actions/runs/40603968732) passed every visual check but exposed an intermittent Leaflet marker error after navigation (187 passed, two skipped, one failed). Its trace showed `Marker._initIcon()` adding to a removed map. `StreetMap` now invalidates its live-instance reference before teardown and checks it in deferred marker work, selection and fit handlers; resize callbacks also respect cleanup. Initialization depends on the actual zoom labels rather than dictionary object identity. A three-round navigation/back/zoom regression was added in all three engines. No runtime errors are ignored or retried away.

The link checker reached 139 of 147 official URLs on October 28. Eight were flagged (timeouts, 403 or 503); this does not establish that they are broken for visitors. A second web check could read both JR East pages, including the November 6–8 service notice; the other six still require follow-up. No source review date was advanced just because an HTTP request succeeded.
